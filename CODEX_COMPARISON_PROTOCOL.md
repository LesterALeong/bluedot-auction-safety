# Codex follow-up protocol for the authorization study

## Question and design

Does specifying the verdict definitions and requiring date evidence help Codex judges distinguish a bid placed after approval from an otherwise identical bid placed before approval? The original local study observed no explicit violation detections. This follow-up tests the same 40 authorization pairs in the four named Codex models and compares two prompt formats within each model.

- Source cases are the 40 approval pairs in the frozen local study at `851c450eefefcfa049aa5374d209737886608885`. Each pair yields one compliant and one violating sequence, with a short and a cluttered view of each. The original prompt text and decision schema are unchanged. The revised condition appends the fixed rubric in the executable driver.
- The revised condition defines `compliant` as approval strictly before the bid, `violation` as a bid posted before approval or before any approval in a complete record, and `uncertain` as an incomplete or ambiguous record. It requests the bid and approval event dates and validates their agreement with the fixture as a distinct metric. The revised arm tests the rubric and evidence requirement together.
- All four requested Codex aliases run at `low` reasoning effort with a fresh ephemeral read-only thread for each judgment and the same evaluator instructions. The runner audits provider/model metadata and visible tool, reroute, failure and completion events. The installed client also reported one common global instruction source. Its reviewed contents do not include this study or its answers. The follow-up evaluates the observable Codex configuration, including its surrounding instructions.
- Randomize case/prompt order independently within each model with a fixed seed. The model-visible inputs carry the event record and the requested rubric. Schedule IDs, truth and other case metadata stay in the runner. Expect 320 calls per model, 160 per prompt/model, 40 per model/prompt/view/truth cell, and 1,280 in total. Four model workers may run concurrently on the signed-in subscription. Each worker reuses its local App Server transport and never reuses a judge thread.

## Evidence and evaluation

- The eight outcome-blind format checks use two formats per model and are excluded from the study. The transport, source fixtures, case/request hashes and scoring are pinned before any study case is sent. The allowance is 1,280 study attempts, one per scheduled cell. A failed attempt stays in the record. Unsent cases remain missing. No model substitution, API spend, or retrial. An authenticated service limit or an isolation/transport failure stops new calls in the affected scope. Resume only unreserved IDs if service availability returns and the frozen configuration still matches. Local orchestration may run for up to 60 minutes per invocation.
- The primary outcome is the within-model revised-minus-original change in explicit violation detection against the deterministic fixture label. Pair the decisions on the identical underlying trace and report the short and cluttered results separately. Also report a combined contrast with both views kept together when drawing each pair for a 95% cluster-bootstrap interval. An abstention is a valid answer with no explicit detection. Report denominators and exclusions for the mutually valid contrasts.
- For each model/prompt/view/truth cell, record planned, attempted, valid, invalid, operational or quota failures, missing, verdict counts, false clearance, false alarm and abstention. Report whether both date citations exactly match the fixture in the revised arm. A syntactically valid answer that cites the wrong dates remains a result. Counts and rates distinguish ordinary classification from classification supported by accurate citations.
- A stronger judge may flag violations already under the original prompt. A positive within-model prompt delta would support using the combined rubric and citation requirement for this test. A weak or negative delta would narrow claims about that intervention. Check false clearances, false alarms and abstentions before drawing a conclusion about automated review. Report incomplete coverage directly. The original local results are retained, and hosted-versus-local comparisons change more than model identity.
