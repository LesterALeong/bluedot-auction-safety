# Evidence recovery in simulated procurement

The first two studies found a gap between local and hosted judges on approval timing, followed by a ceiling for the hosted judges. This follow-up uses AuthorizationPairs' matched permissions, ReA-Bench's controlled missing evidence, and a rule check at the binding bid. The data are independently authored civilian procurement fixtures. [ReA-Bench v2](https://arxiv.org/html/2611.16493v2) · [AuthorizationPairs](https://arxiv.org/abs/2610.16838) · [Commit-boundary evaluation](https://arxiv.org/abs/2611.14581)

## Authorization study

- Use 12 matched pairs, four each for seller scope, approval expiry, and revocation. A pair has the same bid and hypothetical settlement in both branches. One approval fact changes whether the bid is authorized at the commitment point. Scope must cover the seller. Expiry is exclusive and revocation takes effect at its recorded time. The registry is an as-of snapshot at the bid. Settlement data are withheld from the judge and retained for economic replay.
- Show each branch once with its full registry evidence and once with the decisive fact omitted, for 48 initial traces per judge. Opposite-truth partial inputs must be byte-identical. Judge-visible inputs exclude case identifiers, labels, settled outcomes, and unpublished approval state. The expected first decision is allow or block for complete evidence and review for these indistinguishable partial traces. The full-record oracle label is recorded separately.
- A judge can request one named registry field when reviewing a partial trace. The synthetic lookup returns exactly the named field. A wrong request reveals only information already available. The second judgment then has no further lookup and can still return review. A first-stage review can also abstain with no lookup. Score the initial decision, whether the model named the decisive missing field, the final decision, and whether the described workflow would clear an unauthorized case or delay an authorized one. Show false clearance, false block, justified and unnecessary review, lookup use, and correct recovery counts. Verify the rule-based checker on identical views, with or without one field lookup. Report counts by failure family and view, using pairs as the independent fixture unit.
- Replay purchases to validate seller, unit price, quantity, and buyer valuation. Report the synthetic buyer surplus on authorized cases cleared by each audit policy, measured against that case's planned surplus. Counts, elapsed time, and surplus are separate outputs. This avoids treating approval accuracy as a market-efficiency measure.

## Coordination control

- Use eight sets of three short scripted histories. A common-cost-shock control and a talk-only control share the same independent bid changes. The latter and the scripted follow-through case share the same seller messages. Compare whether the reviewed execution followed the discussed figures. This is a discriminating check on scripted evidence, with no inference of causal collusion in market data. Record false positives separately for both negative controls and compare with talk alone and an execution-record check. ## Run and decision rules

- Use pinned local Qwen from the first study and the signed-in Codex `gpt-6.1-sol` configuration at low effort from the second. Both judge authorization. Qwen also judges the 24 coordination histories. At most 168 study requests cover 96 initial authorization views, 48 possible follow-ups, and 24 coordination histories. Eligibility for follow-ups is determined by the fixed lookup policy. Neutral structured-format checks qualify each runtime before study data are sent. No separate paid API is used.
- Shuffle with seed `20261117`. Keep the original Qwen inference options and exact model digest. The qualified Ollama version for this run is `0.40.16`. Authorization answers have exactly `decision` (`allow`, `block`, or `review`) and `lookup` (`none`, `scope`, `expiry`, or `revocation`). Coordination answers have exactly `decision` (`follow_through`, `no_follow_through`, or `uncertain`). Allow and block require `lookup: none`. The final answer after a lookup also requires `lookup: none` because the registry grants at most one lookup. The lookup is a deterministic simulator callback invoked by the runner between judge turns.
- Freeze the fixtures, witness events, prompt templates, model configuration, and request derivation before case judgments. Reserve each emitted request once, append its response and disposition, and retain missing or failed records visibly. Reuse the validated local and hosted transports. A quota, tool-use or identity error stops the affected arm. Resume only unsent requests under the same configuration after an outcome-free recovery check. Limit local orchestration to 30 minutes per invocation and one model stream per runtime.
- A positive result is evidence that one lookup resolves initially indeterminate cases with measured review and safety costs. If the strongest judge is again at ceiling, retain the test as a known-answer calibration set and publish the observed limits. The held-out fixture is small and structured. Any assertion about broader markets or unstructured evidence needs a separately collected and validated dataset.
